# Практична робота №2 — Фінансовий аналізатор

## Вимоги
JDK 17+, Apache Maven 3.8+; Lombok та JUnit 5 завантажуються Maven.

## Запуск
```bash
mvn clean test
mvn exec:java
mvn exec:java -Dexec.args="/шлях/до/pr2.csv"
```
За замовчуванням CSV читається за URL з презентації. Для офлайн-запуску передайте шлях до локального CSV.

## Структура
- `Transaction` — модель із Lombok `@Data`, `@AllArgsConstructor`.
- `DataSource` — абстракція джерела тексту; `UrlDataSource`, `FileDataSource` — реалізації.
- `TransactionCSVReader` — абстрактний утилітний клас зі статичними методами читання/парсингу.
- `TransactionAnalyzer` — абстрактний утилітний клас зі статичними методами обчислення.
- `TransactionReportGenerator` — абстрактний утилітний клас зі статичними методами друку.
- `Main` — координація читання, аналізу та виведення.
- `TransactionAnalyzerTest`, `TransactionCSVReaderTest` — JUnit-тести.

## Примітки
У CSV очікується три колонки: дата (`dd-MM-yyyy`), сума, категорія. Додатні суми — надходження, від'ємні — витрати. CSV-парсер підтримує прості рядки без ком у лапках (як у навчальному файлі). Найбільша витрата — найвід'ємніша сума; найменша — найближча до нуля від'ємна сума. Межі періоду включні. Одна `*` відповідає 1000 грн, залишок округлюється вгору. Стовпці категорій та місяців показують абсолютну суму витрат.

Утилітні класи зроблено `abstract` згідно з умовою роботи; приватні конструктори додатково забороняють створення екземплярів. У звичайних проєктах для цього часто використовують `final` класи з приватним конструктором.
